# §6 Filament 5 admin office (R5, B2)

## §6.1 What it replaces

The current admin is a single 1 585-line client component,
`src/features/admin/admin.view.tsx`, driving **19 tab modules** under
`src/features/admin/tabs/` plus 2 cards under `cards/`, reachable at two pages:
`src/app/admin/page.tsx` and `src/app/admin/login/page.tsx`.

B2 deletes all of it. `src/app/admin/**` goes, `src/features/admin/**` goes, and the seven
`src/app/api/admin/**` route handlers go with them (§5.3).

## §6.2 Panel

Generated by `php artisan filament:install --panels` (§3.4) at
`api/app/Providers/Filament/AdminPanelProvider.php`, served at
`https://api.sdcosmetique.ci/admin` — the default `->path('admin')`, which already matches
B2. Login is Filament's own, authenticating the same `users` table as the API (§4.5).

Access is gated by A4's RBAC, not by a separate admin table:

```php
// app/Models/User.php
public function canAccessPanel(Panel $panel): bool
{
    return $this->isAdmin();     // any role other than 'customer'
}
```

Per-resource visibility uses the Policies from §5.5 — Filament calls `viewAny`, `create`,
`update`, `delete` on them automatically, so there is exactly one authorisation source for
both the API and the panel.

## §6.5 Media

`ProductResource`, `CategoryResource` and `ProductReviewResource` all attach to the
polymorphic `media` table (`docs/db-schema/target-schema.md:270`) through a
`FileUpload`/`SpatieMediaLibrary`-style relation manager.

C12 settles where those files live: Laravel `Storage` on the local `public` disk, exposed by
`php artisan storage:link` and served from `https://api.sdcosmetique.ci/storage/…`.
Today's uploader writes to `public/uploads/<folder>/` and returns a bare `/uploads/...`
path served by the Next server (`src/app/api/upload/route.ts:75-81`). Three consequences of
C12:

- **`media.disk`** (`target-schema.md:275`) is `'public'`.
- **URLs become absolute.** `./web` renders on a different host, so a relative
  `/uploads/...` no longer resolves. `MediaResource` returns
  `Storage::disk('public')->url($path)`, and `next.config.ts:78` must list
  `api.sdcosmetique.ci` in `remotePatterns` while `:177` adds it to `img-src` (§8.4).
- **Nothing to migrate.** `public/uploads/` does not exist, so the store is empty.

The trade C12 accepts: images are served by the API host with no CDN in front. Fine at
current volume, and the `media.disk` column is exactly the seam to change later — swapping
`'public'` for an S3 disk touches one config value and the URL accessor, not the schema.

## §6.6 What Filament does *not* do

It does not serve the storefront, it does not proxy the JSON API, and no Filament page is
ever fetched by `./web`. The panel and the API share only models, policies and the
database.
