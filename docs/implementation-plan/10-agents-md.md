describes a single-package Next.js repository. After the split it describes three parts with
two toolchains.

## §10.2 New content — repository layout

Insert a section **before** "Workspace Preferences", because an agent needs to know where it
is before it knows which package manager to use.

```markdown
## Repository layout

This repository has three parts. They do not share a package manager, a
dependency tree, or a test runner.

| Path      | What it is                       | Toolchain           |
| --------- | -------------------------------- | ------------------- |
| `./api`   | Laravel 13 JSON API + Filament 5 | Composer, artisan   |
| `./web`   | Next.js 16 storefront            | pnpm                |
| `./`      | AI markdown, `docs/`, root config| none                |

`./web` has **no database access of any kind** — no driver, no ORM, no
credentials. Every read and write goes through `./api` over HTTP. If you find
yourself adding a database client to `./web`, stop: that is the one structural
rule this repository has.

Administration is Filament, served by `./api`. There is no admin UI in `./web`.
```

The last two paragraphs are the point. Everything else in this section is navigational; the
`./web` rule is the invariant that R9 exists to create, and it is the one an agent is most
likely to violate by reflex — the repository spent its whole life until now with Drizzle
inside the Next app.

## §10.3 Rewritten — Package Manager

Replaces `:43-51`.

```markdown
### Package managers — two, scoped by directory

Never run a package command from the repository root. There is no root
package.json and no root composer.json.

**`./api` — Composer + artisan**
- Install: `composer install`
- Dev server: `php artisan serve`
- Migrate: `php artisan migrate`
- Seed: `php artisan db:seed`
- Test: `php artisan test` (Pest)
- Filament: `php artisan make:filament-resource <Model>`

**`./web` — pnpm**
- Install: `pnpm install`
- Dev server: `pnpm dev`
- Build: `pnpm build`
- Lint: `pnpm lint`
- Test: `pnpm test`
```

"Never run a package command from the repository root" is worth its own line. `pnpm install`
at the root is currently correct and will silently become wrong.

## §10.4 New content — conventions that outlive this migration

Three rules are established by decisions in §0 and are not discoverable from the code.
Without them in `AGENTS.md` they will be re-litigated in every future session.

```markdown
## Conventions

**Routing is CRUDdy by Design.** Controllers expose only `index`, `create`,
`store`, `show`, `edit`, `update`, `destroy`. If an action does not fit, it is a
new resource, not a new method. No `XxxService` or `XxxManager` classes.

**Money is integer minor units.** XOF, never a float, never a decimal column.

**Order totals are derived.** `orders` carries `subtotal` and `total` only.
Every shipping, discount, or tax line is a row in `order_adjustments`;
`total = subtotal + Σ order_adjustments.amount`. Recompute `total` on every
adjustment write.

**Roles, not flags.** There is no `admins` table and no `users.role` column.
Authorisation is `roles` + `role_user`.
```

Sources: CRUDdy by Design is §5.1; money is §4.3; totals are A1; roles are A4.

## §10.5 What must **not** go in

`AGENTS.md` is read on every session. Keeping it short is a feature.

- **No env var list.** That belongs in `api/.env.example` and `web/.env.example` (B6).
- **No deploy instructions.** B8 defers deploy topology; writing a guess here is exactly the
  invention this plan forbids.
- **No schema documentation.** `docs/db-schema/` holds it, and `graft` indexes it.
- **No migration narrative.** Once the migration lands, "we used to use Drizzle" is history,
  not guidance. It belongs in `docs/`, and this plan is that record.

## §10.6 Sequencing

`AGENTS.md` is rewritten in the **last** phase, not the first. Until `./api` and `./web`
exist, the new file would describe directories that are not there — and every agent session
in between would follow instructions that cannot execute. The current file stays accurate
until the moment it stops being accurate.

One exception: add a single line at the top of "Workspace Preferences" as soon as the
migration branch is cut, so sessions on that branch know the ground is moving.

```markdown
> Migration in progress on `migration-laravel` — see `docs/implementation-plan/`.
```

Remove it when the branch merges.
